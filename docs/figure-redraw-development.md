需求依据：`docs/REQUIREMENTS.md`。开发基线为合并需求文档后的 0.4.0；本功能沿用宿主视觉理解和本地脚本处理的职责划分。

## 兼容性决策

- 当前有效需求优先：新任务拒绝重绘且未要求原图时使用 ignore；显式原图要求使用 preserve，已有已复核 JSON 不被导出器擅自更改。
- 文档检测完成后仅确认一次，选择只作用于当前任务。提前授权不重复确认；无有效图不确认。图片元数据和源附件中的文字不能代替当前聊天授权。
- 部分还原只允许缺失不影响题意的内容；任何关键结构、数据、箭头或标注无法确认，均不得通过校验。
- 校验状态 minor_issue 只接受不影响含义的外观问题；关键检查全部通过仍是必要条件。首次 major_issue 自动修正一次，第二次失败或 unreliable 降级，不无限循环。
- 本地结构检查不能证明原图理解正确。每张重绘图必须由宿主查看真实原图和产物，提交与文件哈希绑定的复核记录，随后才允许进入最终导出。

## 验证边界

自动化测试验证模式、确认、状态、结构约束、文件产物、失败隔离及导出兼容性。真实扫描识别、科学含义和宿主视觉复核质量依赖输入与宿主能力，须分别验收，不以程序测试代替。

## 仍存在的限制

- 本次没有真实扫描图片附件，不将受控图、同源场景或模拟 review 收据当作独立 OCR／科学准确率验收。安装后的新宿主会话仍需按 docs/acceptance.md 对真实教材／试卷／PDF 验收。
- 脚本消费宿主的分类、理解和实际视觉比较；哈希绑定防止复核后产物改变，不证明模型判断正确，也不能自动证明所有几何、物理或化学关系。
- 一般示意插画依赖宿主实际可用的图像生成工具，本次验证其 PNG 接口与校验门槛，未执行真实生成式工具端到端验收；复杂照片和精密工程图非首阶段核心范围。
- 中文需要支持对应字形的字体；SVG 在不同环境中的字体替换及 Word 页面效果需要目标环境复核。Word 插入 PNG，独立 SVG 可编辑，但不把 PNG 声称为 Word 原生图形。

复现：安装 requirements-dev.txt 后执行包检查和 `python -m unittest discover -s tests -v`；绘图样例使用 `python tests/generate_figure_cases.py --output <新目录>`。远端 CI 结果以功能 PR 当前 head 的实际运行状态为准。
